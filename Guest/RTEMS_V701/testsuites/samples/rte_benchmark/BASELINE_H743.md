# RTE on RVM benchmark baseline - STM32H743

## Configuration

- Board: NUCLEO-H743ZI (STM32H743ZIT6), RVM hypervisor, RTE (RTEMS 7.0-rc1) guest.
- Toolchain: `arm-rtems7-gcc` 15.2.0 (RTEMS 7.0-rc1, newlib nano).
- RVP: `gccmf-stm32h743zit6-rte.rvp` - Code 0x080B0000/0x40000, Data block 0x20000 (128 KiB),
  Virt1 Period 10 (10 Hz RTE tick), user stack 0x2000, vector stack 0x1000.
- RTE layout: `RVM_DATA_EXACT = 0x1CF50`, `RVM_DATA_SIZE = 0x1CB50` (1 KiB guard),
  `RVM_VIRT_REG_BASE = 0x3001CF50`, `RVM_VIRT_STATE_BASE = 0x3001CFC0`,
  user stack 0x3001D000/0x2000, vector stack 0x3001F000/0x1000.
- RVM support: the BSP references the M7M02 `Include/` and `Source/` trees
  through `RVM_ROOT` in `rte_config.ini`; the generated `rvm_platform.h` and
  `rvm_platform_a7m_conf.h` are staged into the BSP include directory by
  `rte_copy.sh`, so no RVM implementation or adapter is kept in the BSP
  source tree.  The RVM CPU port is the separate
  `cpukit/score/cpu/arm/v7m_rvm/` directory selected by `cpuarm_rvm`; the
  shared `cpukit/score/cpu/arm` sources remain unmodified.
- Workspace: generated by `Project/benchmark.sh gccmf-stm32h743zit6-rte.rvp`.  This is now
  the RTE_Gen path: rvgen derives `Virt1/Project/rte_config.ini` from the `.rvp`,
  writes the workspace `Virt1/Include/rte_config.h`, and writes the
  `Virt1/Project/prc_virt1` makefile.  That makefile configures the RTEMS BSP
  with waf, builds `rte_benchmark`, converts it with objcopy, and feeds it
  through bincopy into `Virt1/Project/virt1_image.c`.  The Kernel links that
  generated C image; there is no manually embedded prebuilt RTE binary.
- Build order used for this baseline: Monitor -> Proc1 -> Proc2 -> Virt1 (waf)
  -> Kernel.  The Virt makefile re-stages and re-runs `waf configure` with the
  current VM's `rte_config.ini` on every build because the RTEMS build
  directory is shared; Virt builds must be serialized.
  The generator writes `rte_config.h` and `rte_copy.sh` inside the Virt1
  workspace and writes nothing into the RTEMS tree.  Workspace names follow
  the Virt name (`prc_virt1`, `virt1_image.c`); the makefile runs
  `rte_copy.sh` before each waf invocation to stage the generated entry and
  descriptor as `rte_entry.c` and `rte_entry_desc.c` in the BSP `start`
  directory, and `rte_prc.h` plus `rte_config.h` in the BSP include directory.
  Both C files are compiled by waf.  `rte_config.h` is a small wrapper that
  includes `rte_prc.h` and adds the RTE data-region/stack macros.  The
  generated `rte_config.ini` also carries `RTE_FAST_PATH` (default `True`).
  The switch selects the BSP option and the `-DRTE_FAST_PATH` compile define;
  set `RTE_FAST_PATH=0` in the generator environment before regeneration, or
  edit the value in `Virt1/Project/rte_config.ini` and rebuild, for an
  all-Vct image.  The RTE application target is `testsuites/samples/prc_virt1.exe`; the benchmark is a
  separate app enabled for every benchmark Virt (`RTE_APP_ENABLE=True`).  The
  benchmark application is `testsuites/samples/rte_benchmark/init.c`; the per-VM
  app folder `Virt1/Source/app/` contains only `rte_test.h`, which selects
  `rte_benchmark/chip/rte_test_stm32h743zi.h` from the `.rvp` chip.  The whole
  folder is staged to `bsps/arm/v7m_rvm/app/`, and `RTE_APP_SOURCES` points at
  the benchmark `init.c`.  A user multi-file app placed in
  `<Virt>/Source/app/` overrides the benchmark special case; its `.c` files
  become separate `RTE_APP_SOURCES` entries and are compiled/linked normally
  (verified with a two-file app printing `helper=42`).  A sequential
  multi-VM build (8/16 vectors, different data sizes) was used to verify that
  the shared build directory switches layouts correctly.
  `Proj_Gen::Process_Linker` skips and removes the per-Virt `prc_*.ld` for
  RTE because the BSP `linkcmds` is authoritative.  The descriptor's
  `.rodata` is placed in `.PROCESS_DESC` at 0x080B0000 by `linkcmds`,
  and `rvm_entry.c` contains `main()`, `bsp_start()`, `bsp_reset()` and the
  handler registration.
- Benchmark: `testsuites/samples/rte_benchmark/init.c`, RTEMS 7.
  TIM2 is the free-running cycle counter (`BENCH_TIME_GET = TIM2_CNT << 1`),
  TIM4 is the 100 us virtual-vector interrupt source (physical IRQ 30, guest
  vector 2), and the RVM relay reads the RME `START` from the shared page.
- The benchmark tasks use the default RTEMS task attributes, so every
  measured switch uses the basic 22-word frame.

## Results

The per-chip performance archive is in `chip/rte_test_stm32h743zi.h`; it
contains both the default fast-path table and the all-Vct table for the
optimized build.  This file keeps the build configuration and the RMP item
mapping.

## RMP item mapping

- **Yield**: `rtems_task_wake_after(RTEMS_YIELD_PROCESSOR)` with both benchmark
  tasks at the same priority.
- **Semaphore**: counting semaphore release/obtain.
- **FIFO**: RTEMS Chain API (`rtems_chain_append` + `rtems_chain_get`) with one
  node, which is a non-blocking local enqueue/dequeue pair like `RMP_Fifo`.
- **Message queue**: RTEMS message queue send (non-blocking) + blocking receive.
- **Blocking message queue**: one-slot message queue with a blocking receive.
  RTEMS has no sender-blocking send directive, so the blocking side of this
  item is the receive path.
- **Alarm combination (1/2/3/5/7)**: five classic timers with periods 1, 2, 3,
  5 and 7 ticks.  Each timer re-arms itself from its expiry handler; the
  benchmark advances the classic clock with 10000 explicit `rtems_clock_tick()`
  calls while the RVM virtual tick is masked.  Callback counts are checked
  against 10000 / 5000 / 3333 / 2000 / 1428 and no count mismatch was printed.
- **Memory allocation/free pair**: eight malloc/free pairs are measured per
  round and scaled to one pair, matching RMP's unit.
- **ISR Blocking message queue**: the TIM4 virtual-vector handler posts to the
  one-slot queue while the receiver task blocks.
- **ISR RVM activation relay**: TIM2 timestamp read in the guest vector handler
  minus the RME kernel timestamp placed in the shared page.

## Notes

- The Notification item needs a receiver-ready handshake: Task2 sends a ready
  event to Task1 before Task1 starts the 10000 sends, because an RTEMS event is
  a bit flag, not a counter.  Without the handshake the 10000 sends collapse
  into one bit and Task2 blocks forever after the first receive.
- The alarm test masks the RVM virtual tick (`RVM_Hyp_Int_Dis`) for the duration
  of the manual clock ticks and cancels all five timers before re-enabling.
- The interrupt source and the RVM relay use the benchmark Kernel generated by
  `benchmark.sh` (the native Proc1/Proc2 benchmark threads park after their own
  run, so they do not disturb the RTE guest).
- The RTE context switch requires the `register_lr` context-kind marker and the
  `thread_dispatch_disable_level` restoration in the RVM context handler; this
  is what allows the guest tasks to continue across deferred ISR dispatches.
- `RTE_Gen` is no longer a separate pending deliverable: this baseline was built
  from a freshly regenerated workspace whose Virt1 makefile drove waf,
  objcopy and bincopy, with `rte_config.ini` and the BSP layout header generated
  from `gccmf-stm32h743zit6-rte.rvp`.
